### Linux adaptations

- Add experimental Live sessions backed by a pinned, bundled zmx runtime.
  Clean app quits leave pane processes attached to zmx for the next launch, while explicit pane and session
  closes still terminate their daemons.
  Linux Live mode requires zsh as the account login shell and falls back to Fresh shells with an explanation
  in Settings when that requirement is not met.
- Add remote-session discovery and attachment over SSH through `zmx tree` and `zmx attach`, using the same
  host-free control protocol as upstream.
- Add `version`, `restore.capture`, `session.context`, `session.swap`, and `sidebar.width` control coverage,
  including pane-aware state transfer that never reparents an already-realized `GtkGLArea`.
- Add Quick Terminal percentage sizing, cursor shape and blink settings, the three restore-mode choices,
  session context in the title bar, truncated-row tooltips, and foreground-shell reporting.
- Pace restored pane creation on the GLib main loop and let GTK stop render callbacks for hidden stack pages.
  Defer libghostty occlusion until its OpenGL renderer can reliably rebuild a remapped `GtkGLArea`.
- Bundle and verify the pinned zmx source and runtime in CI and every Linux artifact, alongside its license
  and exact source revision.
- Preserve long Live-session commands by resolving the zmx launch at actual surface creation after the spawn
  permit, including newly created split panes.
- Add persisted-window palette entries, desktop Reduce Motion support, recent-history cleanup, desktop
  launcher actions, structured control-socket logging, correct window-key dispatch, and fixes for Ctrl-Tab
  switching, row-popover tint, and split-survivor teardown.

The macOS global Quick Terminal hotkey, floating panel, TCC permission UI, AppKit accessibility, Metal
resource handling, signing, and notarization changes remain macOS-only.
Linux keeps Quick Terminal in-window with an app-local shortcut and implements hidden-surface resource
handling through GTK; libghostty occlusion remains deferred because remapped surfaces can stay blank.

Compatible with Ubuntu 24.04 / Debian 13 or newer and modern Fedora systems with glibc 2.39 or newer.
All artifacts are x86_64; the AppImage additionally bundles GTK4 and libadwaita.
